# Offline runtime and dependencies

The build installs the production manifest with ordinary Bun resolution and
archives the complete runtime project, including its lockfile, node_modules,
workers and assets. It warms Bun's native cache by installing the project
generated by the CLI's own `init --no-install`. Resolved lockfiles and both
archives are retained as qualified build inputs shared across targets.

The executable restores unchanged files into versioned cache directories and
runs the public CLI entrypoint with its embedded Bun using `BUN_BE_BUN=1`.
The child's standard `NODE_PATH` fallback supplies bundled dependencies to bare
projects; project-local packages retain priority. Internal links and executable
permissions survive extraction. `TSCIRCUIT_CACHE_DIR` overrides the cache root.

Package operations use the CLI's existing `TSCIRCUIT_NODE_RUNTIME` hook and a
private bunfig with `install.offline = true`, `ignoreScripts = true` and the
restored native cache. No PATH changes or source rewrites are required.
Uncached packages, versions and URLs fail locally. Cached `latest` tags reflect
preparation time; keep the qualified archives for exact reproduction.

Published CLI 0.1.2438 includes [CLI #5699](https://github.com/tscircuit/cli/pull/5699)
and serves the public `tscircuit/browser` export with its matching evaluator
worker. The JS CDN uses the dynamic importer's public catalog and UI dependency
manifest.

Legacy browser exporters still have asset adapters in
`scripts/ui-package-adapters.ts`; those need upstream browser entrypoint and
asset-resolver fixes. Their build dependencies are separate from the packaged
production runtime.

Runtime fixtures check package data, workers, links, argument/exit forwarding,
module fallback and project precedence. Native cache tests check real offline
install/add/remove, misses and lifecycle suppression. Binary/browser smoke tests
cover the actual CLI, static-site assets and local WASM rendering. Arbitrary
user-authored programs are not sandboxed.
